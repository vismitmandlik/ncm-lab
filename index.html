NCM Troubleshooting Guide

Structured steps for common NCM issues. Follow resolutions in the order listed.

No matching issues found.

Symptom
  • Commands fail or return inconsistent output in Motadata UI terminal.
  • Unexpected device response during execution.
Cause
  • Connectivity issues between Motadata server and device.
  • Incorrect credential permissions or privilege level.
Resolution
  1. Login to the Motadata server.
    ssh <motadata_server_user>@<motadata_server_ip>
  2. From the server, test SSH connectivity to the device.
    ssh <device_user>@<device_ip>
Note

Always validate connectivity from the Motadata server itself. Testing from another machine does not verify collector connectivity.

Symptom
  • Command works during manual SSH session but fails via NCM execution.
Cause
  • Credential profile user mismatches.
  • Insufficient privilege level assigned to configured user.
Resolution

Verify privilege level on the device:

show privilege

Ensure the Motadata credential profile uses identical username and privilege level as the manual login.

Symptom
  • Specific commands fail when executed through a configuration template.
Cause
  • Command requires configuration mode but is executed in normal mode.
Resolution

Add the following commands at the beginning of the action commands section in the template:

configure terminal <your configuration command> end
Note

Ensure configuration commands are placed before the end statement in the template.

Symptom
  • Operation fails with a file already exists error.
Cause
  • Previous firmware or configuration file already exists on device storage.
Resolution

Remove the existing file from the device before reattempting:

delete flash:<filename> # or rm /flash/<filename>
Cause
  • Device response exceeds the configured timeout threshold.
Resolution

Increase the timeout in motadata.json:

"config.request.timeout.seconds": 300
Note

Maximum allowed value is 300 seconds. Restart Motadata services after updating motadata.json.

Cause
  • Probe batch execution exceeds the configured timeout value.
Resolution

Increase the timeout in motadata.json:

"plugin.engine.probe.batch.timeout.seconds": 600
Note

Maximum allowed value is 600 seconds. Restart services after modification.

Symptom
  • Discovery, Backup, or Restore fails immediately.
Cause
  • SSH port blocked by firewall or network ACL.
Resolution

Test port reachability from the Motadata server:

nc -zv <device_ip> 22 # or telnet <device_ip> 22

Ensure firewall rules allow Collector-to-device SSH communication on port 22.

Symptom
  • Backup or Restore stops midway or fails during file transfer.
Cause
  • TFTP / FTP service not running.
  • Port 21 blocked by firewall.
Resolution

Check port reachability and verify the FTP service:

nc -zv <device_ip> 21 systemctl status vsftpd

Verify FTP service availability and network connectivity.

Symptom
  • Backup file is not copied to the storage location during every backup operation.
  • Storage location does not show a new file after each scheduled backup.
Cause
  • When a Storage Profile is attached, NCM copies the backup file only if the backup file version changes.
  • If there is no configuration change on the device, the version remains the same and the file is not copied again.
Resolution

No action required. This is by design to:

  • Avoid duplicate file copies
  • Reduce unnecessary storage usage
  • Prevent redundant file transfers

A file will be copied to the storage profile only when:

  • A configuration change occurs on the device
  • The backup version number increments
Note

If validation is required, verify the current and previous backup versions in NCM before assuming backup failure.

Symptom
  • Restore operation fails even though credentials are correct.
  • Error related to file transfer during restore.
  • Restore does not initiate on the device.
Cause

A TFTP server must be available for Restore, even if the Credential Profile is set to No Protocol. The device pulls the configuration file from the TFTP server — if the service is not running or not reachable, restore will fail.

Resolution

Verify the TFTP server is running:

systemctl status tftpd-hpa

If not running, start it:

sudo systemctl restart tftpd-hpa

Verify TFTP port (UDP 69) is listening:

ss -anu | grep :69
Important
  • Ensure the network device can reach the TFTP server IP.
  • Confirm no firewall, ACL, or security restrictions block UDP port 69.
  • The device must be able to initiate a TFTP connection toward the server.
  • Restore will fail even if authentication succeeds if the device cannot reach the TFTP server.
Symptom
  • Selected SSH algorithms are not fully reflected in handshake logs.
  • Additional algorithms appear during SSH negotiation.
  • Connection succeeds but certain selected algorithms are not visible in logs.
Cause
  • The SSH library may internally append compatible algorithms during negotiation, even if not explicitly selected in the UI.
  • If newer algorithms are selected but not yet supported by the SSH library, the connection may proceed using supported configured algorithms instead.
  • Unsupported or internally handled algorithms may not appear in the handshake logs.
Resolution

No action required if the SSH connection is successful. If verification is needed:

  • Ensure at least one common algorithm exists between the device and the configured UI settings.
  • Confirm the selected algorithms are supported by the SSH library version in use.
  • Review handshake logs with the understanding that not all internally negotiated algorithms may be displayed.
Note

A successful SSH connection confirms algorithm negotiation completed using mutually supported cryptographic settings, even if some selected algorithms are not explicitly shown in logs.

Symptom
  • Configuration operation fails at the enable stage.
  • Error message: en command failed, pattern # does not found
Cause
  • The device prompt pattern returned after the enable command does not match the OOTB template pattern.
  • For example, the template may expect # but the device returns ; or another vendor-specific symbol.
Resolution
  1. Open the Action History of the affected device.
  2. Review the output of the failed configuration operation.
  3. Identify the actual prompt pattern returned by the device after the enable command.
  4. Compare it with the pattern defined in the attached template for that device vendor.
  5. Replace the expected pattern in the template with the correct prompt pattern observed in the device output.
Note

The enable command relies on accurate prompt pattern matching. If the expected pattern does not match the device's actual prompt, execution will fail even if the command itself is valid.

Changelog

New features, improvements, fixes, and security updates — newest first.

v3.0 August 2026 Troubleshooting & UX

Adds a full NCM Troubleshooting Guide with searchable accordion cards, plus a suite of quality-of-life improvements across all tabs.

Features

  • New

    NCM Troubleshooting Guide tab

    A dedicated Troubleshoot tab with structured, searchable resolution cards for seven common NCM issues — SSH connectivity, credential failures, config backup errors, bulk approval workflow, and more. Each card has collapsible Symptom / Cause / Resolution sections with one-click code-block copy. A sticky search bar filters cards in real time; a single Expand all / Collapse all toggle opens or closes every card at once.

  • New

    Decode history dropdown

    A history button next to the Decode action stores the last 10 successfully decoded inputs for the current browser session (via sessionStorage). Click any entry to restore it to the input field instantly — no re-pasting needed.

  • New

    Prettify both — single-click formatting

    A Prettify both button in the JSON / XML tab formats the Left and Right inputs simultaneously, saving a second click before running a diff.

User experience

  • Improved

    Diff empty state & change summary

    The diff area now shows a dashed placeholder with guidance text before any diff is run, replacing an empty blank space. After diffing, a +N / −N badge appears next to the Inline / Split toggle showing how many lines were added and removed.

  • Improved

    JSON key-path label on diff hover

    In inline diff mode, hovering over any changed JSON line reveals a dotted key-path label (e.g. .address.city) computed from the surrounding context, making it immediately clear which nested field changed without manually scanning indentation.

  • Improved

    Keyboard shortcuts across all tabs

    Ctrl ↵ now triggers the primary action on every tab — Decode, Epoch Convert, and Diff. Shortcut hints are displayed inline next to the action buttons.

  • Improved

    Epoch result card with accent border

    The epoch conversion result table is now wrapped in a card with a coloured left border, making it visually distinct from the input fields and easier to scan at a glance.

v2.0 July 2026 Diff views

Expanded diff capabilities in the JSON / XML tab with multiple comparison views.

Features

  • New

    Side-by-Side Diff View

    The JSON / XML diff now supports a Side by Side view in addition to the existing inline unified view. Toggle between the two modes using the Inline / Side by Side control that appears after running a diff. Modified lines are paired row-for-row across the left and right columns, with JSON syntax highlighting preserved in both panes.

  • Improved

    Live View Re-render on Toggle

    Switching between Inline and Side by Side instantly re-renders the current diff without requiring a second Show Diff click. Line numbers are shown in both panes of the side-by-side table for quick navigation.

v1.0 July 2026 Initial release

The first public release of NCM Lab, providing essential utilities for decoding, timestamp conversion, and structured data analysis.

Features

  • New

    Decode Field

    Decode encoded values commonly found in configuration backups and API responses. Supported formats are detected automatically and clearly identified in the output.

  • New

    Epoch Converter

    Convert epoch values to readable timestamps across multiple timezones, or convert dates back to epoch format.

  • New

    JSON / XML Formatter and Diff

    Format and inspect JSON or XML in two independent panels. The diff view focuses on what changed and collapses the rest, making large comparisons easy to read.

User experience

  • Flexible input options

    Paste text, upload a file, or drag and drop content directly into supported tools.

  • Keyboard-friendly workflows

    Common actions submit with the keyboard. No mouse interaction is required for most workflows.

  • Clear feedback and notifications

    Loading states, results, and errors are presented clearly and do not interrupt the current workflow.

  • Light and dark themes

    Choose the theme that fits your environment. The preference follows the system default and is remembered across sessions.

Security

  • Security

    Secure decoding

    Sensitive decoding operations are handled server-side. Encryption keys are never exposed to the browser.

Included in v1.0

  • JSON / XML Formatter
