Changelog

All notable changes to NCM Lab are documented here, newest first. Entries are grouped by release and tagged as New, Improved, Fix, or Security.

v1.0 July 2026 Initial release

First public version of NCM Lab. Covers the three most common NCM backend debugging workflows — decoding encoded field values, converting epoch timestamps, and diffing JSON / XML payloads — with full light & dark theme support.

Core tools

  • New

    Decode Field — auto-detects Snappy and AES-ECB

    Paste or drop any Base64 / Base64URL encoded backend field and the tool automatically determines whether it is Snappy-compressed (used by CodecUtil.compress() for API response fields such as config.backup.file.content) or AES-ECB encrypted (used for raw DB-level sensitive fields). After decoding, a coloured badge — Snappy or AES-ECB — appears next to the Output label so the decode path is always explicit.

  • New

    Epoch Converter — multi-timezone timestamp tool

    Converts any epoch value (milliseconds or seconds, auto-detected by digit count) to human-readable timestamps across ten timezones including the browser's local zone. Reverse conversion from ISO 8601 or RFC 2822 strings back to epoch ms / s is also supported; both directions submit on Enter so the mouse is never needed.

  • New

    JSON / XML Prettifier & Diff

    Prettify or minify JSON and XML payloads in two independent panels with per-panel Copy, Clear, Prettify, and Minify actions. The Diff section computes a line-level LCS diff and renders it with collapsed context — only changed lines and three surrounding lines are shown, keeping large diffs readable without endless scrolling.

Security

  • Security

    AES-ECB cipher key never exposed in the browser

    The cipher key is stored exclusively as a Vercel environment variable and evaluated server-side inside a serverless function at /api/decode. It never appears in HTML source, JavaScript bundles, or any network request payload visible to browser devtools, making it safe to use from client sites.

User experience

  • Improved

    Paste-first decode input with compact file upload

    The decode textarea is the full-width primary surface — large, drag-and-drop aware, and focused on paste. File upload is a compact ghost button in the top-right corner that loads file content directly into the textarea. Typing or pasting into the textarea while a file is loaded automatically detaches the file so switching between modes requires no manual step.

  • Improved

    Auto-scroll to output after decode

    Clicking Decode scrolls the output label smoothly to the top of the viewport once the result arrives, so the decoded content is immediately visible regardless of how tall the input or page is. This applies to both successful decodes and error responses.

  • Improved

    Toast error notifications replace browser alerts

    JSON/XML parse errors and API failures now surface as slide-up toasts anchored to the bottom-right corner, replacing the browser's native alert() dialog that blocks the entire tab and requires a mouse click to dismiss. Toasts auto-dismiss after 3.5 seconds and do not interrupt the current workflow.

  • Improved

    Keyboard shortcuts for power users

    Ctrl+Enter submits the decode textarea. Enter submits both epoch converter inputs. The JSON/XML mode selector is a segmented control that is visually distinct from action buttons, making the current mode state unambiguous at a glance.

  • Improved

    Contextual UI feedback throughout

    The Decode button shows a spinner during the API request. The Copy button is hidden until a successful result exists. "Clear Diff" is disabled until a diff is rendered. Empty output boxes are hidden until populated, removing the hollow bordered rectangles that appeared on load.

Accessibility & typography

  • Improved

    WCAG AA typography — 14 px floor on dark backgrounds

    All text elements meet the WCAG AA 4.5:1 contrast minimum. Secondary and hint text has been raised to a 14 px floor — hint text was previously 13.1 px and file chip labels 12.5 px — removing the eye strain caused by the combination of small size and muted colour on near-black surfaces.

  • Improved

    Fully responsive layout — four breakpoints

    The layout uses full viewport width with generous padding and collapses to a single-column layout at 768 px. Tab overflow scrolls horizontally on narrow screens without wrapping. Breakpoints target 1600 px (large desktop), 1024 px (laptop), 768 px (tablet), and 480 px (mobile).

  • Fix

    Long decoded lines scroll horizontally instead of wrapping

    Previously, long string values in decoded JSON wrapped to column 0, making continuation text appear before the indentation of the line above. The result box now uses white-space: pre so long lines scroll horizontally, preserving indentation structure exactly as it appears in the data.

  • Improved

    Custom dark-themed scrollbar across all scrollable areas

    The browser's default white OS scrollbar has been replaced with a styled scrollbar matching the dark theme — dark track, subtle thumb, accent colour on hover — applied consistently to the result box, diff viewer, textareas, and tab bar. The scrollbar updates automatically when switching to light mode.

Theming

  • New

    Light and dark mode with system preference sync

    A toggle button in the header switches between light and dark themes. The app follows the browser's prefers-color-scheme preference by default; a manually chosen theme is persisted to localStorage and restored with no colour flash on reload via an inline anti-FOUC script in <head>.

  • New

    Semantic CSS custom property token system

    All colours are expressed as --color-bg-*, --color-fg-*, --color-accent-*, --color-success/error/warn-* tokens with WCAG AA contrast ratios verified and documented inline. New themes can be added with a single html.theme-NAME { } CSS block — no other refactoring required.
